## Coordination and handoffs

1. **Lead fixes the task boundary.** Inspect branch/status/user changes; state read-only versus permitted edits, exact files/worktree, external-action restrictions and expected artifact. Read record 18 first, matrix 16 second, audit 15 for implementation evidence; older plans are history where superseded. Ask questions only when authorized work actually depends on an unresolved choice.
2. **Parallel read-only investigation first.** Assign independent platform, distribution and scheduling/backend analysis in available slots. No tools writing live data or running generation/seed scripts that overwrite files. Supply minimum sufficient context, source paths, relevant policy and expected output; do not assume forked agents inherited decisions.
3. **Agree contracts through lead before dependent writes.** Set source-record/draft/revision identity, exact normalization boundary, credits/counts/durations, distinct-course identity, atomic groups/co-teachers, faculty attendance versus teaching/off-days, pattern-specific break permission and typed solver outcomes. Record accepted decisions in record 18 or its explicit successor; do not duplicate conflicting schemas in each specialist's notes. Every affected consumer has an owner/acceptance condition.
4. **Allocate exact files.** Lead maintains one active owner per file. Shared models, router, API, domain records and source-acceptance services are serial integration points. Isolated worktrees may be used for later authorized implementation after checking user changes; they do not remove semantic contract conflicts. Without isolation, parallel analysis followed by sequential editing/integration is the fallback. No runtime setting changes just to increase concurrency.
5. **Keep Codex/Antigravity writing sequential.** Before an Antigravity edit handoff, Codex stops editing and records baseline/ownership; after its return, inspect exact diff and evidence before integrating. They must not simultaneously modify this project. Antigravity gets one bounded task, not an independent architecture mandate. Parallel read-only review is allowed.
6. **Independent review follows author work.** Testing/Reliability reads the actual candidate/diff/input, independently derives expected results and records defects. The author fixes under its ownership; the reviewer verifies the new candidate. A report of passing tests is not independent approval. Review generation, manual/upload/publication bypasses, not only a happy-path solver result.
7. **Lead integrates and reports.** Reconcile recommendations; preserve failed/unknown outcomes and remaining decisions. Run checks appropriate to changed scope, review complete task delta/status and document limits. Stop at the authorized deliverable; no implicit next phase, deployment or push.

Handoff packet (plain Markdown or task text, no custom config format): objective/current authorization; baseline commit and dirty files; exact allowed files and forbidden actions; linked policy and assigned role; agreed input/output contract and consumers; unresolved dependencies; expected acceptance checks; deadline/budget if supplied. Return: evidence by file/symbol, changes/diff, actual checks/results, contradictions, remaining assumptions, next owner and precise blocking question if one is genuinely required. Do not copy workbook personal records, credentials or cached authorization claims into handoffs.

Review fixtures must include distinct-course assignments across multiple sections; permanent attendance with zero teaching on a working day; independent section weekend pairs with batch spread one/two boundary cases; 1/1.5/2-credit theory same-day same-room blocks; rejection of dependent normalization/generation approval when required three-credit count/spread remains unresolved, while permitting source inspection/editing, unrelated corrections and browser work; sessional pair across break disabled/enabled with same lab; unchanged theory/SUST/section break semantics; split/co-teachers; source formulas/cache/corrections; stale drafts and unauthorized own/other-faculty edits; known feasible/infeasible versus timeout/unknown and greedy allocation/network failures.
